# Publish images from a job that runs no test dependencies

Closes #41. Part of #1.

## Summary

The image is built in one job, tested in another, and pushed by a third, the only job that can write packages. The pushing job checks nothing out and installs nothing: it loads the image the build job saved, checks its ID against the build job's output, and pushes it. The build and test jobs have read-only tokens, and no checkout leaves its token on disk, so the UI suite's npm packages and Playwright's browser cannot push an image. Every action is pinned to a commit hash. The daily run also rebuilds an image a week old, so fixes to its other packages arrive without a Dyalog release.

## How it was tested

Go unit tests read the workflow files and run the rebuild decision script. A publish run dispatched on the branch, which never pushes from a branch, exercises the build, test and publishing jobs up to the push.

**Decisions in the tests**

- The workflow tests read `.github/workflows/*.yml` line by line, using the two-space indentation the files use: a job is a key two spaces under `jobs:`, and a step's keys are indented beyond its dash. The module has no dependencies, and a YAML library would be the first.
- A job that can write packages may not check out the repository, set up Go or Node, run npm, npx, `go test`, `go run` or Playwright, or call another workflow, which would pass the permission on. A workflow's own `permissions` may not include `packages: write`, since every job without permissions of its own gets them. At least one job must be able to write packages, so the test cannot pass by removing publishing.
- Every checkout sets `persist-credentials: false`, including those in jobs with read-only tokens: no step uses the stored token, and one rule is simpler to keep.
- The image ID check is read from the workflow: the job that can write packages must refer to the build job's `image-id` output before its `docker push`. The dispatched run shows the check working.
- The rebuild decision is `scripts/needs-build UPSTREAM_DIGEST BUILT_FROM CREATED [NOW]`, which exits 0 to build and 1 not to. The daily check runs at 04:23 and a build finishes minutes later, so an image is a few minutes short of seven days old at the check a week on; the threshold is six and a half days, so that check rebuilds. A missing or unreadable base digest or creation time counts as a change, as a missing base digest does today, and only RFC 3339 times are read: `date` also accepts phrases such as "yesterday".
- The script's tests fix `NOW`, so they do not depend on the clock.

**Expected failures**

- `TestEveryActionIsPinnedToACommitHash`: nine `uses:` lines name major-version tags.
- `TestEveryCheckoutKeepsNoCredentials`: four checkouts persist credentials.
- `TestOnlyAJobThatRunsNothingFromTheRepositoryCanWritePackages`: publish.yml's `image` job has `packages: write` and calls image.yml, whose single job runs every suite.
- `TestThePublishingJobChecksTheImageIDBeforePushing`: no job with `packages: write` of its own pushes; image.yml's job pushes with the permission its caller passes on.
- The four `TestTheDailyRun` tests: `scripts/needs-build` does not exist.

**Evidence**

- Locally: `gofmt` and `go vet` pass, and `go test ./test/workflows/` fails exactly the eight tests above, for the reasons given. A prototype of `scripts/needs-build`, not committed, passes the four script tests.

**Anticipated implementation**

- `.github/workflows/image.yml`, called by CI and the publish workflow, has two jobs with `contents: read`:
  - `build` builds the image, saves it compressed with zstd as the artifact `sandbox-image`, and outputs its ID as `image-id`;
  - `test` loads the artifact, checks its ID, starts the container and runs the integration and UI suites.

  It has no `publish` input and pushes nothing; it outputs `image-id` to its caller.
- `.github/workflows/publish.yml`: `check` and `image` keep read-only tokens. A new `publish` job, the only one with `packages: write`, needs both. It downloads the artifact, loads it, compares its ID with `needs.image.outputs.image-id`, and pushes `latest` and the version tag from `main` only, never with an overridden upstream. From a branch it stops before logging in, so a run dispatched there checks everything but the push.
- The check job calls `scripts/needs-build` with the upstream digest, the published image's base digest and its creation time, read by a new `scripts/published-created`.
- Every action, in all three workflows, pinned to the commit of its current release, with the version in a comment; every checkout with `persist-credentials: false`.
- README and plan: how images are built, tested and published, and the weekly rebuild.
