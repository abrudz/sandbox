# Run the sandbox container without a network

Closes #52. Part of #1.

## Summary

The public instance's sandbox container has no network but loopback. runner-api listens on a Unix socket when `SANDBOX_SOCKET` names one, in a volume it shares with Caddy, which proxies to it. The socket is open to root only, so a connection on it is trusted to name its client in `X-Forwarded-For`. Without the setting, runner-api listens on TCP port 8080 as before, for `docker run -p`, CI and the integration tests.

## How it was tested

Unit tests serve on a socket and check its permissions, its replacement after an unclean exit, and how it identifies clients; config tests read the setting. Deployment tests check, on a runner `setup-host` has provisioned, that the sandbox container has no network and cannot connect out or to the host, that nothing listens on port 8080, and that the per-client limits still tell clients apart through Caddy.

**Decisions in the tests**

- The setting is `SANDBOX_SOCKET`, an absolute path, rather than the issue's example `SANDBOX_LISTEN=unix:...`: one variable with one meaning, and TCP port 8080 when it is unset.
- A connection on the socket names its client in `X-Forwarded-For` with no `SANDBOX_TRUSTED_PROXIES`: the socket file is open to its owner, root, only, so only root on the VM, Caddy among it, can connect. The unit test serves with no trusted proxies and checks that the right-most entry decides, as it does behind a trusted proxy.
- A process that ends without closing its listener, through SIGKILL or a crash, leaves the socket file behind, and listening there again fails with "address already in use". The test leaves one with `SetUnlinkOnClose(false)` and requires a request on the new listener to be served.
- `api.Listen` and `config.Limits.Socket` are declared so that the tests compile. `Listen` keeps today's behaviour, TCP port 8080 whatever its argument, and the field is not read.
- No network is checked both as Docker's network mode and as the interfaces the container sees. The connection test runs bash's `/dev/tcp` as root in the container, to 1.1.1.1 port 80 and to port 80 of the host's first address, where Caddy listens on the host network. Through a bridge both connect.
- `TestNothingListensOnPort8080` replaces `TestSandboxPortListensOnLoopbackOnly`, which required runner-api's published port on loopback.
- `TestPerClientLimitsApplyToTheAddressCaddySaw` sends requests through Caddy from 127.0.0.2 and 127.0.0.3. Two 3 s runs from the first reach its limit of two requests in progress; a third from it must get 429, and a run from the second must be served. If runner-api took every request through the socket to come from one client, the second's run would get 429 as well. The test needs three run slots; GitHub's hosted runner for a public repository has four CPUs, so four. It passes before the change, through the trusted gateway address, and guards client identity through it.

**Expected failures**

- `TestARequestOnTheSocketNamesItsClientInXForwardedFor`, `TestTheSocketIsOpenToItsOwnerOnly`: `Listen` listens on TCP, so there is no socket file.
- `TestListenReplacesASocketLeftByAnEarlierProcess`: nothing accepts on the leftover socket, so the request is refused.
- `TestSandboxSocketSetsTheSocketToListenOn`, `TestSandboxSocketMustBeAnAbsolutePath`: `SANDBOX_SOCKET` is not read.
- `TestSandboxContainerHasNoNetwork`: the container is on the `sandbox` bridge network, with `eth0` beside `lo`.
- `TestSandboxContainerCannotConnectOutOrToTheHost`: both connections succeed.
- `TestNothingListensOnPort8080`: Docker publishes runner-api's port on 127.0.0.1:8080.
- `TestPerClientLimitsApplyToTheAddressCaddySaw` passes.

**Evidence**

- Locally: `gofmt` and `go vet` (also with `-tags deploy`) pass. The unit tests fail as expected: the socket requests and the `stat` with "no such file or directory", the request on the leftover socket with "connection refused", and the config tests with an empty socket and no error. The deployment tests run in CI only.

**Anticipated implementation**

- `internal/api`: `Listen` listens on TCP port 8080 when the socket is empty; otherwise it removes a leftover socket, listens on the Unix socket and makes it `0600`. `clientOf` treats the peer of a request that arrived on a Unix socket as a trusted proxy.
- `internal/config`: `SANDBOX_SOCKET`, refused unless absolute. `cmd/runner-api` serves on `api.Listen(limits.Socket)`.
- `deploy/compose.yaml`: the sandbox service gets `network_mode: none`, `SANDBOX_SOCKET=/run/sandbox/runner-api.sock` and a volume at `/run/sandbox` shared with Caddy, and loses its published port, its network and `SANDBOX_TRUSTED_PROXIES`. `deploy/Caddyfile` proxies to `unix//run/sandbox/runner-api.sock`.
- README and plan: the setting, and the public instance without a network.
