# Run the sandbox container without --privileged

Closes #33. Part of #1. #34 switches the public instance once this image is published.

## Summary

The sandbox container no longer needs `--privileged`. It runs with `CAP_SYS_ADMIN` added, AppArmor and Docker's masked paths unconfined, and `deploy/seccomp.json`: Docker's default seccomp profile with `pivot_root` allowed under `CAP_SYS_ADMIN`. The container keeps Docker's default capabilities otherwise, sees none of the host's devices, and runs every process, the jail included, under Docker's seccomp profile as well as nsjail's policy.

## How it was tested

Integration and UI tests in CI against the container, as for #7.

## Cycles

### Cycle 1: RED

**Test surface**

| Test | Change |
|---|---|
| `TestContainerHoldsNoCapabilityBeyondDockersDefaultsAndSysAdmin` | New |
| `TestContainerHasOnlyDockersDefaultDevices` | New |
| `TestRunCannotTurnOffAddressSpaceRandomisation` | New |

**Coverage**

| Acceptance criterion | Covered by |
|---|---|
| The bounding set holds no capability beyond Docker's defaults and `CAP_SYS_ADMIN` | `TestContainerHoldsNoCapabilityBeyondDockersDefaultsAndSysAdmin` |
| `/dev` holds only Docker's default entries | `TestContainerHasOnlyDockersDefaultDevices` |
| A run cannot turn off address space randomisation | `TestRunCannotTurnOffAddressSpaceRandomisation` |
| Every integration and UI test passes with containers started this way | The whole suite, once CI and the test helpers start containers with the new flags (cycle 2) |

**Decisions in the tests**

- The capability test reads `CapBnd` of the container's PID 1 and fails on any bit outside Docker's 14 default capabilities and `SYS_ADMIN`, listed by name in the test. A Docker release that drops a default capability still passes.
- The device test lists `/dev` and fails on any entry outside the 16 that Docker creates in an unprivileged container.
- `personality(ADDR_NO_RANDOMIZE)` stands for a call that nsjail's policy allows and Docker's profile refuses. Docker's profile allows `personality` only for the values 0, 8, 0x20000, 0x20008 and 0xffffffff, and fails the rest with EPERM. The argument is passed as `U8`, because seccomp compares all 64 bits of it.
- In this cycle CI and the tests still start containers with `--privileged`, so the new tests fail on what they check rather than on a container that does not start.

**Expected failures**

- `TestContainerHoldsNoCapabilityBeyondDockersDefaultsAndSysAdmin`: a privileged container holds every capability.
- `TestContainerHasOnlyDockersDefaultDevices`: a privileged container sees the host's devices.
- `TestRunCannotTurnOffAddressSpaceRandomisation`: without Docker's profile, `personality` returns the previous personality, 0.

**Evidence**

- CI run [45573897558](https://github.com/abrudz/sandbox/actions/runs/45573897558) on `3dbd385`: lint, the unit tests, the other 51 integration tests, the 52 UI tests and the Deployment job pass. Exactly the three new tests fail:
  - the bounding set is `000001ffffffffff`, 26 capabilities beyond the allowed 15, among them `SYS_MODULE`, `SYS_RAWIO`, `SYS_PTRACE` and `NET_ADMIN`;
  - `/dev` holds 160 entries beyond Docker's 16, among them `mem`, `kmsg`, `kvm` and the runner's disks (`nvme0n1` and its partitions);
  - the run prints `0 0`: `personality` succeeded.

**Anticipated implementation**

- `deploy/seccomp.json`: Moby's `seccomp/default.json` at revision `9ee3204f0d0cfa19ca2c6a7b0fcf5a2b353954ae`, with `pivot_root` added to the rule that allows `mount` and the other mount calls under `CAP_SYS_ADMIN`.
- `image/entrypoint` remounts `/sys/fs/cgroup` read-write before delegating controllers.
- CI's shared container and the test helpers' containers start with `--cap-add SYS_ADMIN --security-opt apparmor=unconfined --security-opt systempaths=unconfined --security-opt seccomp=<deploy/seccomp.json>`, from one list in the helpers and one in the workflow.
- The README's local `docker run` uses the same flags; the plan's container section, its risks and `THIRD_PARTY_NOTICES` (Moby's profile, Apache-2.0) follow.

### Cycle 2: GREEN

**Changes**

- `deploy/seccomp.json`: Moby's `seccomp/default.json` at revision `9ee3204f0d0cfa19ca2c6a7b0fcf5a2b353954ae`, byte for byte as fetched, then re-serialised with `pivot_root` added to the rule that allows `mount`, `umount2`, `unshare`, `setns`, `clone3`, the new mount API calls and the rest under `CAP_SYS_ADMIN`. It is the profile the experiment branch ran.
- `image/entrypoint` remounts `/sys/fs/cgroup` read-write before moving processes and delegating controllers. Under `--privileged` the mount is already read-write and the remount changes nothing.
- CI's shared container (`image.yml`) and the containers the tests start (`runFlags` in `helpers_test.go`, used by `startContainer` and `TestImageRunsAJailedProcess`) run with `--cap-add SYS_ADMIN`, `apparmor=unconfined`, `systempaths=unconfined` and `seccomp=` the absolute path of `deploy/seccomp.json`.
- `README.md`: the local `docker run` fetches the profile and uses the four flags, with what each gives nsjail; `--privileged` is named as the broader alternative.
- The plan: the command in Context, the container section with the reason for each flag, the privileges row, the CI and verification commands, the development environment and the risk entry.
- `THIRD_PARTY_NOTICES`: Moby's profile, its revision, its modification and its Apache-2.0 licence, as part of the repository outside the image.
- `deploy/compose.yaml` keeps `privileged: true` until #34.

**Test changes in this cycle**

- CI and the test helpers start containers with the four flags instead of `--privileged`, so the whole suite runs under them. This is the fourth acceptance criterion.

**Evidence**

- Locally: `gofmt`, `go vet` with and without the integration tag, the unit tests, `bash -n` on the entry point and a JSON parse of the profile pass.
- CI run [45575373958](https://github.com/abrudz/sandbox/actions/runs/45575373958) on `90375ee`: all jobs pass, every container started with the four flags. That is lint (shellcheck included) and the unit tests, all 54 integration tests (the three new ones and `TestImageRunsAJailedProcess` among them), all 52 UI tests and the Deployment job.
