# Build the sandbox container skeleton and CI pipeline

Closes #2. Work item 1 of [docs/plans/dyalog-runner.md](../plans/dyalog-runner.md).

## Summary

`image/Containerfile` builds the sandbox image: nsjail built from source, `runner-api` built with Go 1.24, and a final stage on `docker.io/dyalog/dyalog:latest` whose entry point delegates the cpu, memory and pids cgroup controllers and starts `runner-api`. The running container serves `GET /healthz`. The image carries Dyalog's licence at `/LICENSE`, this project's licence at `/usr/share/doc/sandbox/LICENSE`, and the notices for the third-party code it ships at `/THIRD_PARTY_NOTICES`. `.github/workflows/ci.yml` lints, unit-tests, builds the image and runs the integration suite against it on every push.

## How it was tested

Unit tests run in the dev container with `go test ./...`. Container tests run in CI only (plan, Development environment); each cycle below links its CI run.

Integration tests carry the `integration` build tag and read `SANDBOX_URL`, `SANDBOX_IMAGE` and `SANDBOX_CONTAINER`; a missing variable fails the test rather than skipping it. Image tests use `docker run --entrypoint` against the image; container tests use HTTP or `docker exec` against the running container.

**Scaffolding**

- `go.mod` (module `github.com/abrudz/sandbox`, Go 1.24) and `cmd/runner-api`, which serves `api.NewHandler()` on port 8080.
- `internal/api.NewHandler` answers 501 Not Implemented on every path.
- `image/Containerfile` has the `runner-api` build stage and a final stage on `dyalog/dyalog:latest`; it has no nsjail, no notices and no entry point script.
- `.github/workflows/ci.yml`: job `checks` (gofmt, go vet and staticcheck with and without the `integration` tag, shellcheck on scripts under `image/`, `scripts/` and `deploy/`, unit tests) and job `image` (build, start with `--privileged`, wait for the API, integration tests, container logs). The jobs are independent, so a unit-test failure does not hide integration results. Pull request events run CI only for forks; pushes to this repository already run it.

**Anticipated implementation order**

1. `GET /healthz` returns 200.
2. `/THIRD_PARTY_NOTICES`: nsjail and Kafel (Apache License 2.0), the Go standard library (BSD-3-Clause, The Go Authors).
3. nsjail build stage (release 3.6, from source) and its runtime libraries in the final stage.
4. `image/entrypoint`: runs as root, moves itself into a leaf cgroup, enables cpu, memory and pids for child cgroups, then execs `runner-api`. shellcheck covers it.
5. `.dockerignore` to keep the build context to the files the image needs.

### Cycle 2: GREEN

**Changes**

- `internal/api/server.go`: `NewHandler` routes `GET /healthz` (and `HEAD`) to a handler that answers 200 with `ok`. Other paths get 404 and other methods 405 from the standard mux.
- `image/Containerfile`, three stages:
  - `nsjail`: nsjail 3.6 and its Kafel submodule, built on `debian:trixie-slim`, the base of `dyalog/dyalog:latest`. The stage records the Debian packages that provide nsjail's shared libraries (`ldd`, then `dpkg -S`), so the final stage installs the package names of its own release (`libprotobuf32t64` on trixie where nsjail's upstream Dockerfile names bookworm's `libprotobuf32`).
  - `runner-api`: a static Go build.
  - Final stage on `dyalog/dyalog:latest`, as root. It installs the recorded packages, and `RUN ! ldd ... | grep 'not found'` fails the build if any library is missing, for example when the base image moves to a Debian release that `DEBIAN_RELEASE` does not match. It keeps Dyalog's `/LICENSE` and adds `/THIRD_PARTY_NOTICES` and `/usr/share/doc/sandbox/LICENSE`.
- `image/entrypoint`: the cgroup v2 nesting steps of the docker-in-docker image's entry point. Every process in the container's cgroup moves to the leaf cgroup `init`, `cpu`, `memory` and `pids` are enabled for child cgroups, and `runner-api` replaces the shell as PID 1 so it receives `SIGTERM` from `docker stop`.
- `THIRD_PARTY_NOTICES`: nsjail 3.6 and Kafel (Apache License 2.0) and the Go standard library (Go licence), with the full licence texts copied from the upstream repositories at the versions built. Debian packages are covered by their own files in `/usr/share/doc/<package>/copyright`.
- `.dockerignore`: the build context holds only the files the Containerfile copies.

**Evidence**

- Locally: gofmt, go vet and staticcheck (with and without the `integration` tag) report nothing; `go test ./...` passes; shellcheck 0.10.0 reports nothing on `image/entrypoint`.
- CI run [44473086489](https://github.com/abrudz/sandbox/actions/runs/44473086489) on `69736c2`: both jobs pass (36 s and 37 s). The unit test and all five integration tests pass. The build log shows the final stage installing `libprotobuf32t64` and `libnl-route-3-200`.

**Notes**

- A push to a branch with an open pull request starts two runs. The push run does the work; the pull_request run is skipped by the fork-only condition.
- `docker exec` still works after the entry point enables the controllers: `TestContainerDelegatesCgroupControllers` reads `cgroup.subtree_control` through it.
- `runner-api` runs as root inside the privileged container (plan, Risks). Runs will execute as an unprivileged uid in their own user namespace once the executor exists (#3, #5).
