# Kill and remove each run's cgroup before releasing its slot

Closes #61. Part of #1.

## Summary

runner-api gives each run a cgroup of its own below the container's root, with the cpu, memory and pids controllers delegated, and has nsjail create the run's cgroup inside it. Once nsjail has exited, however it exited, runner-api kills whatever is left in that cgroup, waits until it is empty, and removes it, before it returns the run's result and frees its slot. A run whose nsjail dies before its own teardown no longer leaves a cgroup behind, or processes that outlive its slot.

## How it was tested

An integration test starts a run with a background process, kills nsjail with SIGKILL from outside, and requires that nothing the run made is left, processes, job directory or cgroup, as soon as its response arrives. The existing tests do the same for completed, timed-out and cancelled runs.

**Decisions in the tests**

- The run starts `sleep 30` in the background through `⎕SH` and then waits, so that a process other than the interpreter is in the jail when nsjail dies.
- The test kills every nsjail process in the container with SIGKILL through `docker exec`, once the interpreter is running, and checks with the existing `leftovers` helper at once, with no grace period: the response is the moment the slot is freed.

**Expected failures**

- `TestARunWhoseNsjailIsKilledLeavesNothingOnceItsResponseArrives`: the run's cgroup, `/sys/fs/cgroup/NSJAIL.<pid>`, is left behind, and possibly processes that have not yet died.

**Evidence**

- Locally: `gofmt` and `go vet -tags integration` pass. The test runs in CI only.
- CI run [45965561252](https://github.com/abrudz/sandbox/actions/runs/45965561252) on `4820435`: exactly this test fails. Once the response arrives, the run's processes are gone, through nsjail's parent-death signal, but its cgroup is left: `/sys/fs/cgroup/NSJAIL.19`. The other leftover tests, the rest of the integration and deployment suites, the 52 UI tests, lint and the unit tests pass.

### Cycle 2: GREEN

**Changes**

- `internal/sandbox/cgroup.go`, new: `createRunCgroup` makes the run's cgroup and delegates `+cpu +memory +pids` to it; `removeRunCgroup` kills whatever is left in it, through `cgroup.kill` or, on kernels before 5.14, one process at a time, waits until `cgroup.events` reads `populated 0`, logs once if that takes over 5 s, and removes it and the cgroups below it, deepest first.
- `internal/sandbox/nsjail.go`: a new `CgroupRoot` field. With it set, `Run` creates `<CgroupRoot>/job-<id>`, named after the run's job directory, passes it to nsjail as `--cgroupv2_mount`, so that nsjail creates its limited `NSJAIL.<pid>` inside it, and removes it in a deferred call that runs before the job directory's removal and before `Run` returns, and so before the handler frees the slot. Empty leaves nsjail's default, for tests that stand in for nsjail.
- `cmd/runner-api/main.go`: `CgroupRoot` is `/sys/fs/cgroup`, the container's cgroup, whose controllers `image/entrypoint` delegates. The container's cgroups go with the container, so nothing is swept at start-up.
- Plan: the executor's step says how a run's cgroup is created and removed.
- A process that cannot be killed keeps its run's slot rather than outliving it: `removeRunCgroup` waits for the cgroup to empty with no deadline, and logs the wait.
