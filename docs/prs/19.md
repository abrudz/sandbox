# Run permalinks on load and make the logo the Run button

Closes #19. Follows the plan's frontend work ([docs/plans/dyalog-runner.md](../plans/dyalog-runner.md), Frontend), after use of the local instance.

## Summary

Opening a permalink whose header, code or footer is not empty runs its program at once, so a shared link shows its result without a click. The navigation bar has two buttons, Run and the permalink, and the Run button shows the dyalog.run logo, the Dyalog D with a right-facing triangle. The separate logo link to a new program is gone, as is TIO's circled play icon, which looked much like the logo. While a run is in progress the D turns smoothly into a spinning cogwheel, as TIO's ring did, and turns back into the D when the run ends or is interrupted. With reduced motion requested, the cogwheel shows without spinning.

## How it was tested

Playwright tests in CI against the container, as for #7. The animation tests compare images of the Run button: before a run, twice during it, and after it. A local preview server (`api.NewHandler` serving `web/`, with an executor running the dev container's `dyalogscript`) gives earlier feedback for the tests that need no container.

**Decisions in the tests**

- A page without a program means `/` and the bare `#apl-dyalog` fragment. Over a second after each loads, no request may go to `/api/v1/run`, and Output stays empty.
- The visible children of the navigation bar must be `#run` and `#permalink`, in that order. The Run button must contain the logo's path (the D's outline from `D White.svg`), and no link may be named `dyalog.run`.
- The animation tests:
  - **Images.** They compare PNG images of the Run button with the pointer moved away, so hover colours play no part.
  - **Run.** A run of `⎕DL 3` is started with Ctrl-Enter.
  - **During the run.** The image 1.2 s in must differ from the image before the run, and the image 0.3 s later must differ again (spinning). With reduced motion the second image must equal the first.
  - **After the run.** Within 3 s of the run ending, or of a click on Run interrupting it, the image must be identical to the one before the run.
- Smoothness itself is not asserted. Screenshots of the frames go with the implementation for review.

**Expected failures**

- The navigation bar test: the bar also shows the logo link.
- The auto-run and origin tests: Output stays empty, because nothing runs on load.
- The three animation tests: TIO's Run button never shows the D.
  - After a run, its gear stops at an arbitrary angle, so the image differs from the one before.
  - With reduced motion, the gear still spins.
- `opening a page without a program makes no run request` passes already: it pins behaviour the change must keep.

**Evidence**

- Locally, against the preview server: the six tests above fail as listed, and the 13 others that need no container pass. One earlier local run also timed out creating the first page, a cold start of the local browser, not a test outcome.

**Anticipated implementation**

1. Auto-run: on the first load, `init` runs the program when the permalink's header, code or footer is not empty. Going back and forward in the history, which also calls `init`, does not run.
2. `web/index.html`: the `#site` link and TIO's Run icon go. `#run` holds the logo's SVG: the D path, the triangle, and a path for the morph that is drawn only while animating.
3. `web/frontend.js`:
   - **Sampling.** At start-up it samples the D's outline as distances from the logo's centre, the inner and outer edge in each of a few hundred directions. On the open left side of the D the two edges coincide.
   - **Animation.** While a run is in progress, a parameter eases from 0 (the D) to 1 (a cogwheel whose ring and teeth rotate), and back to 0 afterwards. Each frame draws the blend of the two outlines.
   - **End state.** At 0 the original D path is shown again, so the button returns exactly to the logo.
   - **Reduced motion.** With reduced motion requested, the parameter jumps instead of easing and the cogwheel does not rotate.
   - **Triangle.** It shrinks slightly to fit the cogwheel's hole.
4. `web/frontend.css`: TIO's rules for the gear, its cut-out ring and the `.ms` (legacy Edge) variant go, along with the `ms` flag in `frontend.js`.
