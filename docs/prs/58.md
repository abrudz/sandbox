# Pin nsjail to a reviewed commit and report upstream changes

Closes #58. Part of #1.

## Summary

The image builds nsjail from a commit named by its full hash instead of the tag `3.6`, which could be moved to other content. A weekly workflow compares the pinned commit with nsjail's master and keeps one issue open while master has moved past it, saying how far, or that master no longer contains the pinned commit. Caddy stays on `caddy:2`, which the daily update keeps patched.

The commit pin comes from Neil Kirsopp's review (branch `harden-run-isolation` of cursork/sandbox).

## How it was tested

Unit tests run the check's script on each kind of comparison and read the Containerfile and the workflows: the nsjail commit is a full hash, and the one job that writes issues writes nothing else. The integration, UI and deployment suites run against the image built from the pinned commit.

**Decisions in the tests**

- The workflow fetches master's head and GitHub's comparison of the pin with master, and hands them to `scripts/nsjail-upstream`, which decides and writes the issue's body; the tests run the script as the `needs-build` tests run theirs. Its arguments are the pinned commit, master's head, the comparison's status and its count of commits master has past the pin, and the latest release's tag. It exits 0 with a report, 1 when the pin is master's head, and 2 on arguments it cannot read, so that a failed API call never closes the issue.
- GitHub's status `behind` or `diverged` means the pinned commit is not in master's history; the report says so, as a sign of a rewritten history, rather than counting commits.
- The pin test reads `ARG NSJAIL_COMMIT`, which the workflow also reads, and requires that the build uses it and clones no branch or tag.
- The permission test generalises the existing one for packages: exactly one job can write issues, and it can write nothing else.

**Expected failures**

- The four `TestTheNsjailCheck...` tests: `scripts/nsjail-upstream` does not exist.
- `TestTheImageBuildsNsjailFromACommitNamedByItsHash`: the Containerfile clones the tag `3.6`.
- `TestTheOneJobThatWritesIssuesWritesNothingElse`: no job can write issues.

**Evidence**

- Locally: `gofmt` and `go vet` pass, and `go test ./test/workflows/` fails exactly these six tests for the reasons above.
