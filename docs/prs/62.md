# Give the jail its own /etc

Closes #62. Part of #1.

## Summary

The jail's `/etc` is a copy of the image's own `/etc`, made when the image is built, instead of the container's. Docker writes the container's resolvers, address and name into the container's `/etc/resolv.conf`, `/etc/hosts` and `/etc/hostname` at run time; a run no longer sees them. The copy has its own `hosts`, naming only `localhost`, and `hostname`, naming the jail's hostname, and no `resolv.conf`, `shadow` or `gshadow`.

## How it was tested

Integration tests read the three files from a run and require the jail's own versions, and run `awk`, which Debian reaches through `/etc/alternatives`. The .NET tests and the rest of the integration and UI suites run in the jail with the new `/etc`.

**Decisions in the tests**

- The run prints the three files through `⎕SH`, each line prefixed with its file's name, so that one run checks all three. A `hosts` line may name only `localhost`; comment lines are ignored.
- The CI container runs on Docker's default bridge network, so Docker writes all three files there, as it does on the public instance.

**Expected failures**

- `TestARunSeesTheJailsOwnNetworkFilesNotTheContainers`: the run reads Docker's `resolv.conf`, a `hosts` naming the container's ID, and a `hostname` holding that ID.
- `TestShellProgramsFoundThroughAlternativesStillRun` passes already.

**Evidence**

- Locally: `gofmt` and `go vet -tags integration` pass. The tests run in CI only.
- CI run [45965440927](https://github.com/abrudz/sandbox/actions/runs/45965440927) on `37935b3`: exactly `TestARunSeesTheJailsOwnNetworkFilesNotTheContainers` fails. The run reads Docker's `/etc/resolv.conf`; `/etc/hosts` names the container's address and ID (`172.17.0.2 8956be2cd90e`) and Docker's `ip6-*` names; `/etc/hostname` reads the container's ID. `awk`, the .NET tests and the rest of the suites pass.

### Cycle 2: GREEN

**Changes**

- `image/Containerfile`: a build step copies `/etc` to `/usr/share/sandbox/etc`, removes from the copy the build's `resolv.conf`, `hosts` and `hostname` (the build host's), `shadow`, `gshadow` and their backups, and runner-api's `sandbox` directory, and writes a `hosts` naming only `localhost` (`127.0.0.1` and `::1`) and a `hostname` of `sandbox`, the jail's hostname. The step comes after every other change to `/etc`, so the copy has the dynamic linker's cache, `alternatives` and the time zone and locale data the image ends with.
- `image/nsjail.cfg`: the jail binds `/usr/share/sandbox/etc`, read-only, at `/etc`.
- Plan: the jail's `/etc` is the image's own copy.
- A copy of the whole image's `/etc`, rather than a list of chosen files, so that whatever the interpreter, .NET and `⎕SH`'s programs read there keeps working; none of what remains is secret or particular to the host.
