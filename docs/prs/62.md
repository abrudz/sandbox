# Give the jail its own /etc

Closes #62. Part of #1.

## Summary

The jail's `/etc` is a copy of the image's own `/etc`, made when the image is built, instead of the container's. Docker writes the container's resolvers, address and name into the container's `/etc/resolv.conf`, `/etc/hosts` and `/etc/hostname` at run time; a run no longer sees them. The copy has its own `hosts`, naming only `localhost`, and `hostname`, naming the jail's hostname, and no `resolv.conf`, `shadow` or `gshadow`.

## How it was tested

Integration tests read the three files from a run and require the jail's own versions, and run `awk`, which Debian reaches through `/etc/alternatives`. The .NET tests and the rest of the integration and UI suites run in the jail with the new `/etc`.

**Decisions in the tests**

- The run prints the three files through `⎕SH`, each line prefixed with its file's name, so that one run checks all three. A `hosts` line may name only `localhost`; comment lines are ignored.
- The CI container runs on Docker's default bridge network, so Docker writes all three files there, as it does on the public instance.

**Expected failures**

- `TestARunSeesTheJailsOwnNetworkFilesNotTheContainers`: the run reads Docker's `resolv.conf`, a `hosts` naming the container's ID, and a `hostname` holding that ID.
- `TestShellProgramsFoundThroughAlternativesStillRun` passes already.
