# Refuse non-JSON run requests and NUL arguments, and group IPv6 clients by /64

Closes #38. Part of #1.

## Summary

A run request must have `Content-Type: application/json`, or it gets 415 before its body is read. A browser sends a cross-origin JSON request only after a CORS preflight, which the service never grants, so other web pages can no longer make their visitors' browsers start runs. An argument containing NUL gets 400 instead of reaching nsjail and failing as 503. IPv6 clients are identified by their /64, so one host cannot count as many clients.

## How it was tested

Go unit tests against the handler, and integration tests against the image for the 415 and the NUL argument.

**Decisions in the tests**

- The refused content types are the three a plain HTML form can send (`application/x-www-form-urlencoded`, `multipart/form-data`, `text/plain`), which need no preflight, and no `Content-Type` at all. Media types are compared without case and parameters are allowed, as HTTP defines them.
- A refused body records whether it was read, so the test shows the 415 comes before the body is read.
- `TestARunRequestFromAnotherOriginGetsNoCORSPermission` passes already: the 415 protects visitors only while a preflight gets no `Access-Control-Allow-Origin`, and the test guards that.
- `TestIPv4MappedAddressesKeepTheirFullAddress` passes already. It guards against grouping an IPv4 client written as `::ffff:a.b.c.d` with every other IPv4 client in `::ffff:0:0/64`.
- The NUL tests send `\u0000` inside a JSON string, the only way a NUL can reach an argument. With the fake executor the run succeeds, so the unit test also checks that no run started; the integration test shows the 503 the real executor gives.

**Expected failures**

- `TestPostRunAnswers415BeforeReadingABodyThatIsNotJSON`: the content type is ignored, so the body is read and the empty body gets 400.
- `TestPostRunAnswers400ForAnArgumentContainingNUL`: the argument passes validation, so the fake executor runs it (200).
- `TestIPv6PeersInTheSame64AreOneClient`, `TestIPv6ClientsNamedByATrustedProxyAreGroupedBy64`: clients are keyed by full address, so the second address in the /64 gets 200.
- `TestTheServiceAnswers415ForARunRequestThatIsNotJSON`: 200.
- `TestTheServiceAnswers400ForAnArgumentContainingNUL`: 503.

**Anticipated implementation**

A prototype of this, not committed, passes every unit test three times under the race detector.

- `internal/api/server.go`: `run` answers 415 unless `mime.ParseMediaType` gives `application/json`, before counting the request or reading its body; `decode` refuses an argument containing NUL with 400.
- `internal/api/limits.go`: `clientOf` keys an IPv6 client by its /64 prefix, after unmapping IPv4-mapped addresses; trust in a proxy is still decided on its full address.
- README and plan: the `Content-Type` requirement, the 415, and IPv6 clients grouped by /64.

### Cycle 2: GREEN

**Changes**

- `internal/api/server.go`: `run` answers 415 unless `mime.ParseMediaType` gives `application/json`, before it counts the request or reads the body. `decode` refuses an argument containing NUL with 400.
- `internal/api/limits.go`: `clientKey` keys an IPv6 client by its /64 prefix, after IPv4-mapped addresses have been unmapped, so they keep their full IPv4 address. Whether a peer or an `X-Forwarded-For` entry is a trusted proxy is still decided on its full address.
