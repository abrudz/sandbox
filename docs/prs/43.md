# Keep crashes and job files from outliving their run

Closes #43. Part of #1.

## Summary

`deploy/setup-host` masks apport and sets `kernel.core_pattern` to a file name, in a sysctl file that applies at every boot, so no crash starts a helper on the host; a run, whose core file limit is 0, then writes no core file at all. runner-api removes the job directories an earlier process left behind before it serves, so a submission's files do not outlive an abrupt exit.

## How it was tested

An integration test restarts a container with a job directory left in it, and deployment tests check the crash handling on a runner `setup-host` has provisioned.

**Coverage**

| Acceptance criterion | Covered by |
|---|---|
| After `setup-host`, `kernel.core_pattern` does not start with `\|`, apport is disabled and inactive, and both survive a reboot | `TestNoCrashStartsAHelperOnTheHost`, `TestApportCannotStart` |
| A job directory left in `/tmp/sandbox-jobs` is gone once the container restarts | `TestJobDirectoriesLeftByAnEarlierProcessAreRemovedAtStartUp` |
| Rerunning `setup-host` changes nothing | `TestRerunningSetupHostChangesNothing` |

**Decisions in the tests**

- A reboot cannot be tested on the runner. `TestNoCrashStartsAHelperOnTheHost` first runs `sysctl --system`, which applies the sysctl files as a boot does, and then reads `kernel.core_pattern`; `TestApportCannotStart` requires apport's service, which sets the pattern to itself when it starts, to be masked, so that nothing starts it at boot either.
- If apport is not installed, `TestApportCannotStart` has nothing to check. Ubuntu's cloud images install it; the runner's image may not.
- The integration test leaves a directory in its own container's `/tmp/sandbox-jobs` with `docker exec`, restarts the container, which keeps its files, and waits up to 30 s for the container to be running without the directory.
- Whether a crash in a run writes a core file is not tested: with a pattern that names a file and a run's core file limit of 0, the kernel writes none, and the tests above establish the pattern.

**Expected failures**

- `TestJobDirectoriesLeftByAnEarlierProcessAreRemovedAtStartUp`: runner-api only creates the jobs directory, so the leftover remains.
- `TestNoCrashStartsAHelperOnTheHost`, `TestApportCannotStart`: depend on the runner's image. If it pipes crashes to apport or systemd-coredump, the first fails; if it has apport, the second fails.

**Evidence**

- Locally: `gofmt` and `go vet` (with `-tags integration` and `-tags deploy`) pass. The integration and deployment tests run in CI only.

**Anticipated implementation**

- `deploy/60-sandbox-core.conf`, installed in `/etc/sysctl.d/`: `kernel.core_pattern = core`. Its name sorts after systemd-coredump's `50-coredump.conf`, so it wins at boot.
- `deploy/setup-host`: masks and stops `apport.service` when it exists, installs the sysctl file, and applies the pattern when it differs, reporting each change.
- `cmd/runner-api`: removes `/tmp/sandbox-jobs` and its contents before creating it, at start-up, before it serves.
- README and plan: crashes and leftover job files.
