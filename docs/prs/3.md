# Run Dyalog programs with dyalogscript through the run API

Closes #3. Work item 2 of [docs/plans/dyalog-runner.md](../plans/dyalog-runner.md).

## Summary

`POST /api/v1/run` runs the submitted code with `dyalogscript` inside nsjail and returns stdout, stderr, the exit status and wall, user and system time in the documented JSON shape. `GET /api/v1/version` reports the interpreter's version, which is also included in every run result.

## How it was tested

Unit tests run in the dev container with `go test ./...`; they drive the HTTP layer through a fake executor. Integration tests submit Dyalog programs to the container in CI (plan, Development environment); each cycle below links its CI run.

**Decisions in the tests**

- `dyalogVersion` is the interpreter's version item verbatim, `2⊃'.'⎕WG'APLVersion'` (for example `21.0.55109.0`), rather than the shortened form in the plan's example. `/api/v1/version` reports only `dyalogVersion`; `imageDigest` and `commit` arrive with publishing (#8), which sets them at build time.
- `TestRunPassesArgumentsToTheProgram` takes the last two items of `GetCommandLineArgs`; with `dyalogscript` the program's arguments follow the script name. An argument containing a space (`bar baz`) must arrive as one item.
- `TestRunDoesNotRepeatStdoutOnStderr` uses a program that reads no input. Dyalog 20.0 echoes input read by `⍞` to stderr; the criterion does not cover that echo, and this test does not pin it.

**Anticipated implementation order**

1. `internal/api`: decode the request into a `sandbox.Job`; encode the `Result` with times in milliseconds, `null` exit code or signal when absent and invalid UTF-8 replaced; 503 when the executor returns an error; `/api/v1/version`.
2. `image/run`: copy `/job/code` into the jail's home directory, append a final newline when missing, and exec `dyalogscript` with the arguments; the input arrives on stdin.
3. `image/nsjail.cfg`: one run per invocation as an unprivileged uid and gid, read-only binds of the system and Dyalog directories, tmpfs for `/tmp` and the home directory, `/proc`, `/dev/null`, `/dev/zero` and `/dev/urandom`, and an environment with `HOME`, `PATH`, `LANG` and `MAXWS`. A fixed time limit stops a runaway program until #4 makes limits configurable.
4. `internal/sandbox.Nsjail`: per-run directory holding the code, nsjail with `--config` and `--bindmount_ro <dir>:/job`, input on stdin, stdout and stderr captured, nsjail's own log on a separate descriptor sent to the service log, exit code or signal, wall time and the child's user and system time; the per-run directory is removed afterwards.
5. `image/Containerfile`: install `run` and `nsjail.cfg`; record `2⊃'.'⎕WG'APLVersion'` at build time in `/usr/share/sandbox/dyalog-version`, which `runner-api` reads at start-up.
