# Drop the sandbox container's unneeded capabilities

Closes #53. Part of #1.

## Summary

The sandbox container drops every capability and adds back only `CAP_SYS_ADMIN`, `CAP_SETUID` and `CAP_SETGID`: the entry point remounts the cgroup filesystem and Docker's seccomp profile allows nsjail's namespace, mount and `pivot_root` calls only with `CAP_SYS_ADMIN`, and nsjail maps the jail's uid and gid, which are not its own, with the other two. The jail's own capabilities come from its new user namespace, not from the container. The compose file, the README's `docker run` command, CI's container and the integration tests' containers use the same set.

## How it was tested

An integration test reads the CI container's effective and bounding capability sets, and a deployment test reads the compose-started container's capability settings and sets, on a runner `setup-host` has provisioned. Every other suite runs in containers with the reduced set.

**Decisions in the tests**

- Both tests read `CapEff` and `CapBnd` of the container's PID 1, tini, which runs as root like runner-api and nsjail, and require each to be exactly bits 6, 7 and 21: `SETGID`, `SETUID` and `SYS_ADMIN`. The bounding set limits every process in the container; the effective set is what root there can use.
- The deployment test also requires `HostConfig` to drop `ALL` and add exactly those three, with or without the `CAP_` prefix, which Docker accepts both ways.
- The rest of the suites are the evidence that the set suffices: every run, limit and isolation test runs in a container started with it. If they show that another capability is needed, it joins the set in both tests, with its reason.

**Expected failures**

- `TestContainerHoldsOnlySysAdminSetuidAndSetgid`: the CI container holds Docker's 14 default capabilities and `SYS_ADMIN`.
- `TestSandboxContainerIsNotPrivilegedAndHoldsOnlySysAdminSetuidAndSetgid`: the compose-started container drops nothing, adds `SYS_ADMIN` alone, and holds the same 15 capabilities.

**Evidence**

- Locally: `gofmt` and `go vet` (with `-tags integration` and `-tags deploy`) pass. Both tests run in CI only.

**Anticipated implementation**

- `deploy/compose.yaml`: `cap_drop: [ALL]` and `cap_add` of `SYS_ADMIN`, `SETUID` and `SETGID`.
- `--cap-drop ALL --cap-add SYS_ADMIN --cap-add SETUID --cap-add SETGID` in the README's `docker run`, `.github/workflows/image.yml`, `runFlags` in `test/integration/helpers_test.go` and the plan's two `docker run` commands.
- README and plan: the reason for each capability.
