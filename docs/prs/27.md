# Show the Run button's logo as the favicon, animated with the button

Closes #27. Follows the plan's frontend work ([docs/plans/dyalog-runner.md](../plans/dyalog-runner.md), Frontend).

## Summary

The page's favicon is the Run button's logo, dark on a light browser theme and light on a dark one. While a run is in progress the favicon follows the button: the D turns into the cogwheel, the cogwheel turns, and the D returns when the run ends. A tab with a run in progress can then be told from the others. A hidden tab gets no animation frames and runs timers about once a second, so there a timer turns the favicon's cogwheel by a third of a tooth on each tick, and the favicon changes back at once when the run ends.

## How it was tested

Playwright tests in CI against the container, as for #7, and locally against the preview server. They read the favicon's address from the page, and open each favicon in a page of its own with a light or dark colour scheme to read its colours.

**Decisions in the tests**

- The favicon is the `href` of the page's `link[rel=icon]`, which is what the browser shows.
- The logo favicon:
  - It must be an http(s) address answering 200 with an `image/svg+xml` type.
  - It must contain the D's path and the triangle's path exactly as the Run button has them.
  - Opened with a light colour scheme, both its paths must be filled `rgb(32, 32, 32)`; with a dark one, `rgb(240, 240, 240)`.
- Running, as with the button's own animation tests, with `⎕DL 3`:
  - The favicon 1.2 s into the run must differ from the one before it, and 0.3 s later must differ again.
  - The second must have the logo favicon's colours in both schemes.
  - Within 3 s of the run ending, the favicon must be the logo again.
- Hidden tab:
  - Before the page loads, `document.hidden` and `document.visibilityState` are made to report a hidden page, and `requestAnimationFrame` never calls back, as in a background tab. Real background throttling cannot be produced in headless Chromium.
  - With `⎕DL 4`, the favicon 1.5 s in must differ from the one before the run, and 1.2 s later must differ again.
  - Within 0.5 s of the Run button leaving its running state, the favicon must be the logo again.
- Reduced motion: as for running, except that the second favicon must equal the first.

**Expected failures**

- The favicon is the placeholder `data:,`, which is not an http address, and it never changes, so all four tests fail.

**Evidence**

- Locally, against the preview server: the four tests fail as listed. A probe confirmed that a favicon drawn as an SVG data URL can be opened in its own page with an emulated colour scheme, and that its `prefers-color-scheme` rule applies there.

**Anticipated implementation**

1. `web/favicon.svg`: the D and triangle paths in the button's 224 by 247 box, with a `style` element filling paths `#202020`, and `#F0F0F0` under `prefers-color-scheme: dark`. `index.html` links it as the icon in place of `data:,`.
2. `web/frontend.js`:
   - **Running favicon.** `drawLogo` also draws the favicon. At rest it is `/favicon.svg`. Otherwise it is an SVG data URL with the morph outline and the triangle's transform, in the same style. On animation frames it is redrawn at most every 100 ms; any other change draws it at once.
   - **Hidden tabs.** On `visibilitychange`, and in `setRunning`, a hidden page completes the morph at once and draws it. While running, a timer then turns the cogwheel a third of a tooth (15°) per second and redraws. In one second the time-based rotation is 45°, a whole tooth, so drawn that way the favicon would look still.
   - **Visible again.** The animation frames resume from the current angle.
   - **Reduced motion.** The cogwheel is drawn at once and does not turn, as for the button.
